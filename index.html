Benchmarks

A benchmark is a fixed set of tasks plus a fixed way of scoring, so two robot policies can be compared fairly. These twenty-five test very different things; six of them are built on the RoboCasa kitchens, and seven are manipulation benchmarks built around memory. Pick a tab; each one is built to be understood in about 30 seconds. Dotted words explain themselves when you hover or tap them.

    The loop every benchmark measures

    Every task here is the same loop, repeated many times a second until the episode ends. Benchmarks differ in what the world looks like, what data you get to learn from, and how success is counted.

    Several rows say "7 numbers (Δ pose + gripper)". That's the same layout, but the units, rotation format and gripper sign differ. The LIBERO tab has a side-by-side comparison. RoboTwin's default action is joint angles rather than a gripper pose. RLBench lets you choose, but its standard 18-task setup sends one absolute gripper pose per keyframe. Meta-World's is the smallest: the gripper can only move in x, y, z and open or close, never rotate. LIBERO-Mem, MEMOBench and RoboMemArena all run on LIBERO's simulator, so they share its 7 numbers. MemMimic's 8 numbers are an absolute target pose, not a step. M3-Bench-robot, NaVQA, RAVEN-QA and RoboVQA have no action at all: nothing moves while they're scored, and the model only answers questions about a recorded video. A NaVQA or RAVEN-QA answer can be a place on the map, though, which a real robot can then drive to. The six RoboCasa rows share kitchens and assets but not tasks, robots or scoring, so a score on one says little about the others. "Best reported" numbers aren't comparable across rows; each benchmark tab explains what its number means.

    RoboCasa365

    A robot in 2,500 virtual kitchens learning 365 everyday chores, from pressing a button to brewing coffee. The 2026 successor to the original RoboCasa.

    Simulation framework + dataset for multi-task and foundation-model training
    The world

    The data

    One timestep of data

    Each demonstration is a recording of this loop, dozens of times per second. A policy learns to copy the action given the observation (imitation learning). Since July 2026 the composite datasets also label every frame with its sub-task, skill name and instruction.

    • A wrist camera (robot0_eye_in_hand)
    • Proprioception: arm joint angles, gripper opening, base position
    • A language instruction, e.g. "Place the toast on the dining counter"

    ΔxΔyΔzΔrxΔryΔrzgripfwdsideyawtorsomode
    • 0–5 · arm. Same controller as LIBERO: robosuite OSC delta pose, [−1, 1] → ±5 cm and ±0.5 rad (axis-angle) per step. Here the frame is the mobile base, because the base can move.
    • 6 · gripper. −1 open, +1 close.

    Atomic skills: the building blocks

    An atomic task is one short skill. RoboCasa365 has 65 of them, covering ten skill families: pick and place, doors, drawers, knobs, levers, buttons, insertion, navigation, sliding racks, and lids.

    Composite tasks: real chores

    A composite task chains several atomic skills into something a person would actually ask for. The task list was drafted with help from an LLM (GPT-4) so it reflects common household activities. These are long-horizon: many steps, but everything stays visible.

    Different robot bodies

    RoboCasa supports several embodiments: single-arm mobile robots, humanoids and quadrupeds with arms. The action vector depends on the body. The arm and gripper part stays similar, but the base, torso and mode slots above are specific to PandaOmron.

    How it's scored

    Success rate per task, averaged over task groups. RoboCasa365 is set up for three settings: multi-task learning, foundation-model training, and lifelong learning. A public leaderboard (live since April 2026) compares community submissions. Note: v1.0.1 raised every task's time limit by 1.5×, so use the latest version when comparing numbers.

    Why it exists

    LIBERO tests on the same tasks it trains on: same instruction, same objects, same room, with start positions jittered so little you can barely see it. So a policy can score 95% by remembering one arm motion per scene instead of looking at what's on the table or reading the instruction. The authors found that the policies they tested keep grasping when the target object is removed, carry out "pick up the salad dressing" when the instruction is replaced by "xxx", and reach for where an object usually is rather than where it is. LIBERO-PRO makes changes a policy that understood the task would handle, and checks whether it does. LIBERO-Plus is related but different: it mostly changes things that shouldn't matter (camera, lighting, noise) to test robustness. LIBERO-PRO also changes things that should change the behaviour (where the object is, which object to pick) to test understanding.

    Five kinds of change

    One perturbation at a time, except that object, position, wording and environment can be combined. Examples from the paper and the project page.

    Object

    Change an object's colour, texture or size, keeping what it is. The policy should still pick the same thing.

    salad dressing → the same bottle, recoloured red

    Position

    Move or swap objects to new, physically valid spots. The policy has to go where the object is now.

    swap the positions of the black bowl and the plate

    Semantic

    Reword the instruction without changing what it asks for.

    "Grab salad dressing and set it in basket."

    Task

    Same scene, different goal: pick a different object or reach a different state, built from parts seen in training.

    "Pick the tomato sauce and place it in the basket" instead of the salad dressing

    Environment

    Move the whole task to a different table or background.

    main table → "living room table"

    One timestep of data

    Training uses no tasks at all. MimicDroid cuts the play data into short segments and finds, for each one, the 10 most similar segments elsewhere in the data. Some of those become the context and the original the target, so the model learns to copy whatever the context shows.

    Observation

    • Context: a few short example clips of the task, with their actions. At test time these are demos of the new task
    • Current RGB images (3 cameras in simulation). In training, random patches are masked out so the policy stops relying on what the hand looks like
    • Proprioception: wrist pose and a grasp signal
    • No instruction: only the examples say what the task is

    Policy
    an in-context policy: reads the examples, then acts
    →

    xyzrxryrzgrasp

    Why it exists

    Why it exists

    NaVQA's method, ReMEmbR, remembers by writing a caption for each stretch of video and searching the captions. That works for what a captioner thinks is worth mentioning, and fails for everything else: a shelf of chicken thighs becomes "packaged meat in a refrigerator", and a small helmet on a seat isn't mentioned at all.     Why it exists

    Most manipulation benchmarks are long but Markovian: what's on the table already tells the policy what to do next, so a policy that sees only the present frame does well.     Why it exists

    Most memory benchmarks test in-trial memory: something was shown earlier in the episode and is needed later. MemMimic adds cross-trial memory.     Why it exists

    A success rate tells you that a policy failed, not why. A memory failure can happen at three points: the policy never took in the fact (storage); it took it in but didn't revise it when the world changed (update); or it kept every detail but couldn't reduce a long history to the one thing that matters now, like "the stove was turned on and then off" (compression). MEMOBench puts checkpoints in each episode, each one a check in the simulator tagged with one of these operations, so you can see which one broke. The main finding: policies store well and update badly. π0.5 with a memory module passes 58% of storage checkpoints but only 17% of update checkpoints.

    Why it exists

    Most VLAs see only the current frame, or a handful of recent ones. The paper measures, for every task, the information gap: how long the cue the action depends on is provably out of sight. 70 of the 90 tasks have one, and 28 have a gap longer than 16 steps, the widest fixed history window among the VLAs the authors surveyed. Median gaps range from 15 to 805 steps depending on the memory type. A policy whose window is shorter than the gap can only guess. Random actions succeed once in 4,500 episodes, so a guessing policy has to actually do the motion right to score at all.

    Why it exists

    Earlier memory benchmarks either have short episodes, or long ones where only a few steps need memory. RoboMemArena's tasks run for 1,076 steps on average (1,832 for the longest), and 68.9% of their subtasks depend on history, the highest share the authors found among robot benchmarks.     Each task is a CoppeliaSim scene plus a short Python file.     Robot datasets are usually built top-down: researchers pick a short list of tasks, then reset the scene between every demo. RoboVQA went the other way. People in the offices asked for anything they wanted ("I am done drinking the coffee, can you throw it in a trash can and get me some laffy taffy"), an operator did it in one go without resets, and the steps were labelled afterwards. That was 2.2× faster with the robot and 13.8× faster with a human body, and the requests match what real users ask for. The point is to test whether a model understands a real, messy scene well enough to plan. Off-the-shelf VLMs didn't: zero-shot PaLM-E needed a human to correct 81% of its plans.

    Eight kinds of question

    All generated for free from the labelled step sequence, by asking at a known point in time. Examples are real questions from the validation set.

    Planning

    Given the request, what's the next step?

    current goal is: Throw hint water bottle into the can & bottle trash. Q: immediate next step? → place the bottle in the recycle bin

    Planning with context

    The same, but with the steps done so far listed.

    … last 20 steps: 1- open the drawer of the table 2- put the white packet in the drawer. Q: immediate next step? → put the black bag in the drawer

    Remaining 5 steps

    Plan further ahead: the next five steps in order.

    … Q: next 5 steps? → 1- put the white packet in the drawer 2- put the black bag in the drawer 3- …

    Success

    Did the step in this clip actually get done?

    place the book on the table. Q: satisfied? → yes

    Discriminative affordance

    Is this step possible from here? Negatives are random steps from other episodes.

    unstack the bowl. Q: possible right now? → no

    Generative affordance

    Name a step that's possible right now.

    Q: what action is possible right now? → close the drawer

    Past description

    Describe what the clip just showed.

    Q: what just happened? → Put the lid in the dustbin

    Future prediction

    Guess what's about to happen.

    Q: what is likely to happen next? → clean the table with the tissue

    How it's scored

    Two ways. VQA error rate: the model answers about 1,000 held-out questions from 50 episodes it never saw. Answers that exactly match a previously graded answer are scored automatically; the rest go to human raters, who see the same clip and question, mark the answer right or wrong, and can supply a correct one, which is saved for next time. Planning with intervention: the model plans a whole long-horizon request step by step while an operator watches. When a plan step is wrong, the operator corrects it (a cognitive intervention); when the low-level policy can't do a step, the operator takes over the arm (a physical intervention). The score is the share of steps that needed a correction, so every task still gets finished. Later papers often skip the raters and report BLEU, a word-overlap score against the reference answer.

    One timestep of data

    The policy predicts where the gripper should be, and the evaluator turns that into joint targets with inverse kinematics. Each task also has a scripted expert (a sequence of skills like "pick", "place", "open door") that generates the training demos.

    • State: gripper position, orientation and opening (ee_state), plus joint positions and velocities

    Action · 7 numbers (ee mode)

    xyzrollpitchyawgrip
    • 0–2 · position of the gripper in metres, absolute. The bundled policies measure it from the robot base, i.e. world axes with the base position (0, −0.4, 0.78) subtracted.
    • 3–5 · orientation as Euler angles, xyz order, in radians. The state uses a (w, x, y, z) quaternion, and the adapters convert between the two.
    • 6 · gripper: ≥ 0.1 → open (fingers at 4 cm), otherwise closed.
    • One action = one control step. The evaluator solves IK for 7 joint angles and applies them for one environment step (100 physics substeps). Policies usually predict a chunk of such poses and replay them.

    Under the hood env.step takes 9 numbers: 7 absolute joint angles + 2 finger positions. A joint control mode lets a policy output those directly. LeRobot's wrapper exposes the 7-number pose action, scaled to [−1, 1].

    Composite tasks

    Long-horizon chores (long-horizon) that chain several skills and often need a plan first: sort objects into groups, make coffee, set a study table for a given subject, or answer a word problem by arranging number cubes.

    How it's scored

    Evaluation uses fixed episode files grouped into tracks. Each track has 10 primitive tasks × 50 episodes and changes one thing. Track 1 is in-distribution. Track 2 uses unseen object categories and instances. Track 3 uses common-sense descriptions of the target. Track 4 uses semantically rich instructions. Track 5 is open cross-task transfer. Track 6 uses unseen textures. Three metrics: success rate; progress score, the fraction of sub-conditions met (a correct grasp counts); and intention score, whether the gripper got within 10 cm of the right object even if it failed. A separate VLM track asks language models to plan skill sequences. Episodes are capped at 200 policy steps by default.

    Action · 4 numbers

    ΔxΔyΔzgrip
    • 0–2 · position change of the gripper, [−1, 1] → ±1 cm per step, in the world frame. The target is clipped to a box above the table.
    • 3 · gripper: +1 close, −1 open (the same sign as LIBERO).

    What's in the 39 numbers

    The state has the same slots for every task, so some are padding. A task with one object leaves the second object's slots at zero. The goal slots are filled in the multi-task splits but zeroed in the meta-learning splits: there, the policy has to work out the goal from the rewards it gets while trying.

    How it's scored

    Success rate, never reward. Each task sets a success flag (e.g. object within a few cm of the goal), and an episode counts as a success if the flag is ever 1 within 500 steps. MT splits: one episode per training goal position (50) per task, averaged over tasks. ML splits: for each held-out goal and task, the agent first collects adaptation episodes (10 by default), then is scored on 3 episodes. LeRobot / VLA protocol: 10 episodes per task with random object positions, 500 in total for MT50, reported per difficulty group. RL results also depend on the reward version (v1 or v2), so compare numbers only within one version and one protocol.
