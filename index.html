Benchmarks

A benchmark is a fixed set of tasks plus a fixed way of scoring, so two robot policies can be compared fairly. These four test very different things. Pick a tab; each one is built to be understood in about 30 seconds. Dotted words explain themselves when you hover or tap them.

The loop every benchmark measures

Every task here is the same loop, repeated many times a second until the episode ends. Benchmarks differ in what the world looks like, what data you get to learn from, and how success is counted.

Each demonstration is a recording of this loop, dozens of times per second. A policy learns to copy the action given the observation (imitation learning). Since July 2026 the composite datasets also label every frame with its sub-task, skill name and instruction.

Atomic skills: the building blocks

An atomic task is one short skill. RoboCasa365 has 65 of them, covering ten skill families: pick and place, doors, drawers, knobs, levers, buttons, insertion, navigation, sliding racks, and lids.

Composite tasks: real chores

A composite task chains several atomic skills into something a person would actually ask for. The task list was drafted with help from an LLM (GPT-4) so it reflects common household activities. These are long-horizon: many steps, but everything stays visible.

Different robot bodies

RoboCasa supports several embodiments: single-arm mobile robots, humanoids and quadrupeds with arms.

How it's scored

Success rate per task, averaged over task groups. RoboCasa365 is set up for three settings: multi-task learning, foundation-model training, and lifelong learning. A public leaderboard (live since April 2026) compares community submissions. Note: v1.0.1 raised every task's time limit by 1.5×, so use the latest version when comparing numbers.

Why it exists

Most robot tasks are Markovian: the current camera frame shows everything you need. In MIKASA the key fact is shown once and then hidden, so a policy that only looks at the present frame can do no better than guess. Long is not the same as memory. A RoboCasa chore can take hundreds of steps without needing any memory.

How it's scored

Success rate, reported per horizon split with fixed seeds: Short (38 tasks, 25–200 steps, 1–8 s), Medium (30 tasks, 201–600 steps), Long (22 tasks, 601–2,160 steps, up to 86 s). The original RL-only release had 32 tasks and 4 memory types; it's still on the mikasa-robo-rl branch.

Lifelong learning · knowledge transfer · tabletop

LIBERO

A robot learns 130 tasks one after another. Does learning task 10 help with task 11, and does it still remember task 1?

Benchmark type
Lifelong learning benchmark; now also the most common VLA scorecard
The world
Franka arm at tables and kitchen counters, built on robosuite
The data
50 human teleoperated demos per task, with images, robot state and language
The tasks
130 tasks in 4 suites, each designed to test one kind of knowledge

The four suites

Robots need two kinds of knowledge: declarative (what objects are and where they are) and procedural (how to move). The first three suites each change only one thing, so you can see which kind of knowledge transfers.

LIBERO-Spatial · 10 tasks

Same objects, different layouts. Tests spatial relationships.

"pick up the black bowl between the plate and the ramekin and place it on the plate"

LIBERO-Object · 10 tasks

Different objects, same layout. Tests recognising objects.

"pick up the alphabet soup and place it in the basket"

LIBERO-Goal · 10 tasks

Same objects and layout, different goals. Tests behaviour.

"open the middle drawer of the cabinet"

LIBERO-100 · 100 tasks

Everything varies at once (entangled). Split into LIBERO-90 for pretraining and LIBERO-10 for longer test tasks.

"put both the soup and the sauce in the basket"

The 2-minute explainer

Official LIBERO intro video: how tasks are generated from human activities, the four suites, and the main findings.

How it's scored

In the lifelong setting, tasks arrive one at a time. LIBERO reports forward transfer (FWT), negative backward transfer (NBT), which measures forgetting, and area under the success curve (AUC). Most VLA papers skip the lifelong part and simply report success rate on each suite after training on all of them together.

Zero-shot evaluation · egocentric · lightweight

EgoGym

A small, fast simulator for grading policies that are already trained. The robot sees from a camera on its gripper.

Benchmark type
Evaluation-only suite for zero-shot policies (e.g. CAP, π₀.₅)
The world
MuJoCo table and cabinet scenes with random textures and distractors
The data
No training set. You bring a policy; EgoGym measures it
The tasks
Pick, Open, Close

Where the policies come from

EgoGym was released with Contact-Anchored Policies (CAP). CAP learns from real-world human data collected with a handheld gripper, then runs in EgoGym with no extra training. These clips show that real-world data. It is not part of EgoGym; it shows what the evaluated policies learned from.

How it's scored

Success rate over many randomised episodes (1,000 by default). An episode succeeds when the reward crosses a threshold: lift over 5 cm for Pick, 0.5 for Open. Optional unprivileged wrappers use a vision-language model (Molmo, Gemini, GPT, Moondream) to find the target, so the policy never gets hidden simulator information.
